# 0.3.0 固定校准协议

2026-11-06 在本版首次两个运行仍进行时记录本协议。后续不按已出现的分数改变本批题包、权重或预算。

- 模型：用户 MiniMax 连接的 `MiniMax-M3.1-Flash`、`MiniMax-M3`，分别报告。
- Agent：`harnesses/json_action` 1.3.0，完整会话及 reasoning 续接；无针对本题的解题策略。
- 请求参数：`max_tokens=8192`、`reasoning_split=true`。未指定的供应商采样默认值由原始请求/响应保留；不声称固定随机种子。
- 预算：224 次动作，2400 秒墙钟上限；业务时钟回放08:30–11:30。模型网络耗时不推进业务时间。
- 题包：本版源码生成后冻结，以发布、Agent、Workflow、Evaluator摘要核对相同协议；提示词包含在冻结快照内。
- 评分：风险重建40、联合资金可行性30、付款15、实际缓冲5、资金控制10。整本台账共享GBP5m误差预算；风险项的时间分为正式通知前全额、通知后至到期前一半。
- 校准压力场景：每个模型连续3次，全部纳入各自均分、样本标准差/方差、最小值和最大值。环境故障单独列出，不记零分；任何替补都保留失败记录。
- 保留验收：校准完成且不改版本后，每个模型执行1次未用于改题的保留金额变体，单独报告。单次保留结果不能证明稳定难度。
- 对照：相同提示和权限的 `quiet` 与 `hedged`，每个模型各1次，检查能否避免无谓资金动作；不并入压力场景的均分。两者仍需履行第二笔义务及日内值班职责。

本批共计划12次真实运行（压力重复6、保留2、对照4）。即使出现个别30–40分，也完成既定重复和对照；不从旧版本或对照中挑选低分宣称达标。若均分不在目标区间，报告失败并用新版本继续设计。

这是一个场景家族下、两个模型配合本地 JSON Agent 的校准。正式挑战还需要更多强模型、成熟 Agent、更多保留场景和重复，不能将当前结果泛化为全体模型能力。
