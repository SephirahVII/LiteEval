# 极端行情下的金融工作流评测

设计版本 0.9，2026-11-06。流程验收案例为 `ldi-margin-001`；`treasury_network`完成八级设计递进和0.8.0同版重复校准，实测仍高于目标，保留为运营能力基线。`source_treasury`进一步检验原始证据风险重建，正在同版重复校准。

正式挑战题以当期强模型与成熟 Agent 在冻结的 Harness、预算和 rubric 下，实测均分约 30–40/100 为难度校准目标。项目出题要求保存在根目录 AGENTS.md。分数分布、重复次数和保留情景随试跑报告记录。

流程验收包位于 `benchmarks/financial_stress/`，实现 L0 两条冲击分支和平稳对照、回放、限时执行、可信流水和离线 Judge。[验收包说明](../../benchmarks/financial_stress/README.md)。新挑战题源位于 [treasury_network](../../benchmarks/treasury_network/README.md)，生成标准原生题包后使用注册的 Workflow 与 Agent Harness 执行。

## 评测定位

评测对象是负责流动性值班的金融 Agent。一个 Case 对应一次连续值班，包含多次外部事件及多轮模型与工具交互。Agent 先完成日常对账和预测，再根据当时可见的数据识别风险、形成指令、确认执行结果、随新信息修正方案并交接。首期选择有明确现金流和截止时间的工作，便于把处置质量落到可复算的状态。

| 能力 | 可观察行为 |
| --- | --- |
| 异常发现 | 从预测、账本和交收条件推导未来资金缺口，区分预测和已确认义务 |
| 即时响应 | 识别最新有效通知，说明金额、截止时间和下一步动作 |
| 决策与执行 | 按金额、额度、权限、抵押品和到账时间提交可执行指令 |
| 动态纠偏 | 收到拒单或新增义务后更新资金缺口，并在备选渠道截止前行动 |
| 长程状态管理 | 跨阶段核对到账、付款和占用资金，避免重复记账或重复发单 |
| 审计交接 | 用账本和事件 ID 说明余额、未解除风险、后续期限及责任人 |

采用真实事件机制校准压力，再用可执行的合成账本定义反事实。首题参考 2022 年英国国债市场事件。英国央行记录了长端国债快速重定价、LDI 机构收到抵押品追缴，以及集中卖出进一步削弱市场流动性的反馈。本题沿用这种冲击和运营约束，机构、资金、合同条款和逐分钟事件均为仿真设定。事后报告供案例设计者校准，Agent 仅接收各时点已发布的信息。[英国央行 2022 年 12 月金融稳定报告](https://www.bankofengland.co.uk/financial-stability-report/2022/december-2022)

## Case `ldi-margin-001`

**角色。** 你是某养老资金管理机构的流动性值班员。请核对本班次的现金、未来交收和抵押品，持续处理新通知，必要时通过授权工具筹资和付款。保证金以英镑现金交收。付款后尽量保有 £5m 可用现金，并在 11:00 前完成交接。以上职责适用于所有情景。情景标签、未来追缴次数和失败分支由控制器保管。

### 开场上下文与工作区

开场上下文提供岗位、08:30 的业务时钟、11:00 的交接要求、工具定义和资料索引。指令可写为「你是流动性值班员。请核对现金与预计交收，按授权处理收到的通知，保持值班直到交接。工具结果包含业务时钟和回执，制度与期初资料见 workspace_index.md。」所有分支使用同一开场模板。

| 数据面 | 内容与可见性 |
| --- | --- |
| 期初资料 | `workspace_index.md` 说明各文件口径。`cash_ledger.csv` 记录期初可用现金。`positions.csv` 记录资产及抵押占用。`forecast_open.json` 记录 £8m 预计保证金。全部以 08:30 为截面 |
| 制度资料 | `funding_terms.json` 记录额度、折扣、成本、截止和到账。`authority_matrix.json` 记录角色与审批权限。`desk_runbook.md` 记录来源分级、£5m 缓冲目标、交收队列及升级路径 |
| 实时工具 | 仿真器分时释放市场、预测、托管行通知与交易回执。账本接口提供当前余额、指令状态、数据版本及时间。更新按事件游标交给同一会话 |
| 工作记录 | Agent 可以维护备忘、计算表和交接文件。可用余额、权限与成交状态以平台账本为准 |
| 控制器私有资料 | 未来事件、情景 ID、完整行情、参考轨迹与 Judge 保存在 Agent 可见范围之外。期初材料来自冻结快照 |

金额以 GBP 最小货币单位入账，表中以 £m 表示。风控预测应标明 `as_of`、`available_at`、`version` 和确认状态，资金和抵押品使用稳定账户及资产 ID。工具使用精确可读的字段名，首次调用前给出接口契约，便于跨模型比较。

### 新闻与证据优先级

首版靠内部预测、账本、授权与回执即可完成。新闻作为升级情景的辅助输入，由固定的点时新闻流提供。每条材料带 `published_at`、`available_at`、来源、资产标签和更正关联。Agent 可以据此调查或提高监控频率，正式追缴金额、交收时点和资金可用性分别由有效的通知及账本确定。公开网页研究可作为独立变体，与封闭回放分别报告。

用成对情景检查证据使用。向两条情景投放同一条「长端国债收益率急升」快讯。一条的内部现金与预测仍充足，另一条显示可验证的现金缺口。这样能观察 Agent 是否按自身敞口与交收条件行动。新闻内容采用可复现的快照或合成快讯。更正与后续报道在各自可见时间释放。

| 资金来源 | 额度与约束 | 时间与成本 |
| --- | --- | --- |
| A 回购 | 未质押国债市值 44，折扣率 10%，最多融入 39.6。融入金额为 x 时锁定市值 x / 0.9 的抵押品 | 09:10 前提交，正常 09:25 到账。到账金额的 5bp 为模拟费用 |
| B 备用授信 | 最多提款 40。先取得资金主管授权，授权最多覆盖申请金额，授权本身不产生资金义务 | 申请授权后 6 个业务分钟回执，09:22 前提交提款，09:32 到账。提款金额的 25bp 为模拟费用 |
| C 货币基金赎回 | 最多赎回 18，额度按已受理的累计金额扣减 | 09:55 前提交，10:15 到账。赎回金额的 3bp 为模拟费用 |

费用单独入账，在本次演练结束后扣收。表内到账金额用于日内现金计算。允许按已公布条款提前申请 B 授权或预先赎回。仿真器校验授权、累计额度、抵押品占用和截止时间。保证金付款可以预约，只有到交收时账上有足够可用现金才结清。回执中的 `accepted`、`pending`、`settled`、`rejected` 分别记录受理、在途、结算和拒绝。

### 常规值班与异常发现

| 仿真时间 | 给 Agent 的材料 | 可观察的任务 |
| --- | --- | --- |
| 08:30 | 期初账本显示可用现金 £20m，风控系统预测 09:40 保证金 £8m，暂无正式付款通知 | 对账并记录预计付款后现金 £12m、当前可用融资渠道及其截止时间 |
| 08:40 | 风控预测小幅更新至 £9m | 更新预测和监控状态，允许继续值班 |
| 08:50 | 冲击情景中预测更新至 £32m，09:40 交收时点保持不变。账本仍为 £20m。平稳对照中的预测为 £10m | 自行结合两份数据识别预计现金缺口 £12m，含缓冲需筹 £17m。确认信息性质，并决定核验、上报、询价或预申请备用授权 |

08:50 的更新沿用普通风控数据的字段与送达方式。Agent 可以通过 `risk.report` 提交证据 ID、预计到期时间、预计资金需求、可用现金、缺口、确认状态和下一步。系统根据证据和当时的可见状态判定风险发现。提前授权可缩短后续决策时间，已发生的资金费用和占用随轨迹计入。预测记录可支持准备动作，正式付款仍需要有效的义务 ID。

完整测评分三条情景。冲击且 A 拒绝、冲击且 A 正常，以及无资金短缺的平稳值班。前两条在 09:12 前共享同样的外部事件。平稳情景在 09:00 确认 £10m 保证金，09:40 正常交收，无第二笔追缴，仍需完成对账和交接。独立的通知版从 09:00 的公开初始状态开始，以 M1 为首条事件，用于诊断接警后处置。

## 时钟、状态与工具

- **调试回放。** 用可控虚拟时钟触发事件，回归测试逐步推进并复算账本。由控制器按预设业务耗时和等待动作推进时钟。模型实测可在固定调用预算下使用此模式，单独报告决策与状态管理表现。
- **限时测评。** 沙箱与连接就绪后启动独立时钟。每 1 秒真实时间对应 6 秒业务时间，完整版 08:30 至 11:00 共 25 分钟，通知版 09:00 至 11:00 共 20 分钟。事件按时钟释放，Agent 慢调用不会推迟通知、截止或交收。首轮试跑将 M1 发布至首次有效确认设为 90 秒目标，并记录实际延迟分布用于校准。
- **时间证据。** 服务端记录事件发生时间、可见时间、Agent 实际读取时间、指令受理和结算时间。分别报告通知发布至确认、发布至首条有效指令、拒单至替代指令的延迟。模型网络耗时计入端到端延迟，可单列排查。环境故障单独标记，避免和 Agent 错过业务截止混算。
- **动作接口。** `events.poll(cursor)` 读取已发布事件，`ledger.snapshot()` 查询现金、义务、抵押品和在途指令，`approval.request(amount)` 发起确定性审批，`instruction.submit(kind, obligation_id, amount, idempotency_key)` 提交授权动作，`instruction.status(id)` 查询回执。`risk.report` 记录结构化风险报告，`incident.ack(event_id, amount, due_at, next_step)` 保存正式通知的确认。审批、交收、去重和版本检查由仿真器执行。
- **证据归属。** 平台侧记录事件流、请求和回执、现金及抵押品流水，Agent 写 `handover.md` 并可附决策简注。仿真器写入的证据保存在 Agent 无写权限的目录或存储中。Judge 使用私有情景脚本和可信流水复算。各工具仅返回当前时刻可见的状态。

限时版用控制器的单调时钟换算业务时间。08:30 开场时发布期初任务并开始计时，Agent 阅读、调用模型、等待工具和提交均占用真实时间。事件及交收按预设时刻发生，工具指令按服务端到达时的状态和截止规则判断。回放日志保留到达、受理及结算时间，按同一顺序重放同一时点的操作。模型只接收当前业务时间和适用截止。

6 倍时钟下，09:12 拒单至 09:22 提款截止共有 100 秒真实时间。若在拒单时才开始申请 B 授权，6 个业务分钟用掉 60 秒，剩 40 秒确认授权及提交提款。先用参考策略核对路径可行性，再用具备财务流程知识的试跑者与目标模型校准倍速和响应目标。时钟比例单独记入结果，与 Agent 的工具调用预算一起冻结。25 分钟表示仿真运行时长。

### 每轮模型执行

外部事件是环境的时间节点，模型轮次是一次模型调用及其工具回执。一次外部事件可能触发多次查询和执行，也允许 Agent 记录观察后等待。控制器在事件发布、异步回执到达或 Agent 约定的检查点唤醒 Harness。模型每轮收到同一会话的工作目标、当前时间、未读事件、上一次工具回执及必要的状态引用。接续沿用 Agent 的工作记录、已提交指令和仿真器账本。

例如在 08:50，第一轮读到风控预测更新并查询账本，下一轮根据账本返回的 £20m 判断缺口，提交风险报告或申请授权。授权在 6 个业务分钟后返回，随后 Agent 根据授权状态和当时可见事件继续行动。模型调用期间到达的消息进入待处理队列，指令按受理时的状态、授权和截止时间校验，回执回到同一会话。所有模型使用同一事件释放规则和工具权限。

## 评分

异常发现与接警后处置分别报告。完整版记录从 08:50 信号可见到首次有效风险报告的延迟、正式 M1 前是否发现、是否区分预测与已确认义务、是否在平稳情景误报严重短缺，以及预备动作产生的成本。只有引用当时可见证据并说明资金缺口的报告计为发现。平稳对照记录误报和不必要的动作，并核对正常交收与交接。通知版直接报告处置表现。

冲击后的处置采用以下 100 分权重。

| 维度 | 分值 | 判定依据 |
| --- | ---: | --- |
| 首次响应 | 20 | 首条确认正确引用 M1、金额、截止时间和行动，记录确认延迟与首条有效资金指令延迟 |
| 资金执行 | 30 | 两笔付款分别按时结清，核对付款前可用现金与回执 |
| 纠偏与去重 | 25 | 用最新回执剔除失效资金，在仍可执行的窗口内切换，第二笔通知后更新缺口，对重传执行幂等处理 |
| 缓冲与成本 | 15 | 两个付款节点的缓冲达标情况、实际融资成本、过量融资占用。在同一情景和可见信息下对照参考策略 |
| 交接与证据 | 10 | 余额和资金占用与账本一致，列出未偿义务、到期处理、责任人及证据 ID |

两笔付款按时结清和遵守授权与额度为必过项。评分同时保留门槛失败前的各维度分数，便于定位失败阶段。因格式错误或额度不足收到的普通拒单可修正。费用仅在满足付款约束的轨迹间比较。审批服务不可用或可信流水缺失导致无法裁决时，标记 `unscored` 并记录环境故障。首版使用程序规则验收关键字段和状态，交接表达可另行盲审。

## 难度与模型能力验证

已有 MiniMax-M3.1-Flash 的三情景真实回放，得分 100、82.5、100，均分 94.17，五笔付款全部准时完成，两条冲击情景均提前发现缺口。每条执行一次，总计 97 次模型请求。原运行 ID 为 `5305db3c494c4050a14423048d79f547`。该结果使现有版本定位为流程验收，后续正式挑战使用新版本。

每题的 24–37 次交互中，7 次用于读文件，8–13 次用于等待，工具未发生被拒请求。题目主要要求完成单账户缺口计算并跟随固定的融资与交收关系。模型的高分和轨迹共同说明，这组复杂度不足以达到用户要求。

| 级别 | 增加的业务约束 | 典型失败 |
| --- | --- | --- |
| L0 流程验收 | 单账户、单笔预测、明确融资条件。回购正常与拒绝分支共用同一前缀 | 会算缺口，忘记下单，或把受理当到账 |
| L1 现金对账 | 合成账面余额 £20m 中有 £6m 受限，另有 £12m 预计来款晚于首笔付款截止。此变体首笔正式追缴设为 £45m，两条融资路径仍各自可行 | 将受限现金或截止后到款算入可用资金。£32m 预测下应识别 £18m 缺口，含缓冲为 £23m。收到 £45m 正式通知后，含缓冲需筹 £36m |
| L2 动态纠偏 | 资金拒单、权威通知改版、重复送达、同一市场新闻对应不同内部敞口。保留可行的备选融资路径 | 沿用失效金额、重复下单，或因新闻大幅融资而增加无谓成本 |

验收后用同一套指标做小规模试跑。比较规则策略、目标模型的调试回放和限时实测，分别定位算错、选错、执行错与超时。若 L0 反复满分，保留它作为验收题，再用 L1/L2 测区分度。若只有限时版大面积失败，先看模型、工具和队列各自耗时，再调整倍速或任务窗口。

## 现有 instruction 和评分的难度审查

## 下一版挑战案例 ldi-liquidity-network-001

### 业务状态与耦合约束

沿用 08:30–11:00 的值班和同一国债冲击机制。基金 P 持有 GBP 与 USD 账户，另一法人基金 Q 有独立资金和签字权限。原始记录分为银行余额、限制性现金、托管占用、保证金通知、融资条款和交易状态。以下均为新案例的合成金额，单位为百万。

| 资源或义务 | 可执行规则 |
| --- | --- |
| P 的 GBP 账面余额 20 | 其中 6 为受限现金，日内可用为 14 |
| P 的 USD 余额 12 | 09:50 须支付 USD 5，按已公布的 FX 价格 0.8 GBP/USD，最多用 USD 7 换得 GBP 5.6 |
| Q 的 GBP 余额 15 | 属于另一法人。跨基金划转须取得双方授权，该情景最早 09:50 才能办结 |
| P 的国债抵押池 | 开场合格未占用市值 29，10% 折扣，对应预估容量 26.1。正式报价从 09:06 开始，报价版本与抵押占用共同决定可成交额 |
| B 备用授信 | 容量 12，授权回执耗时 8 个业务分钟，提款最迟 09:20 受理，09:28 到账 |
| 备用短票出售 | 独立未占用资产市值 4，压力折价 2%，净入账 3.92。最迟 09:27 受理，09:35 到账 |
| 货币基金 | 可赎回 10，最迟 09:55 受理，10:15 到账 |
| GBP M1 | 09:00 正式通知 40，09:40 付款。09:08 同一义务的新版本将金额改为 44 |
| GBP M2 | 09:30 发布金额 8，10:30 付款 |

费用按各路线公开条款，在演练结束后单独扣收。所有现金和抵押品由仿真器按实体、账户、币种、状态和交收时间记账，提交失败或未完成的交易继续占用或释放资源的条件在其接口契约中明确。

### 事件变化和参考可行轨迹

09:05 新估值将 P 的合格未占用抵押池调整至 24，正式回购报价的折扣为 15%，可融资 20.4。09:08 更新 M1 后，Agent 需同时覆盖 GBP 44、USD 5 以及 GBP 5 的付款后缓冲。09:11 另外送达一份较早时点的风险估计，该材料的 as_of 和通知版本支持识别其有效性。

在 FX 能于 09:30 入账的分支中，一条可行路径为 P 的 GBP 可用 14，加回购 20.4、USD 7 换汇所得 GBP 5.6、备用授信 9，共 GBP 49。支付修订后的 M1 44 后剩 5。USD 余 5，足以支付 U1。赎回货币基金 8 支付 M2 后，GBP 缓冲仍为 5。

另一个分支在 09:16 返回 FX 待匹配申请失败，释放预留美元，GBP 入账为 0。使用已授权的 B 12，并出售独立短票取得 3.92，则 GBP 为 14 + 20.4 + 12 + 3.92 = 50.32，支付 M1 后余 6.32。随后赎回 8 支付 M2，GBP 仍余 6.32。USD 仍可覆盖 U1。

对照分支维持原抵押池与 M1。回购 25.4、FX 入账 5.6 加初始可用 GBP 14，恰好覆盖 GBP 40 付款及 GBP 5 缓冲，授信保持未提款。三条轨迹均须验证实际受理、授权、匹配及交收的时序。历史估计的修订依据、跨基金资金限制和各币种义务由业务记录提供。

该设计要求 Agent 同时发现限定现金、跨币种到期义务、抵押池变化和通知改版，并根据回执选择不同的融资组合。不同分支沿用相同岗位指令，事件时点、金额、账户及档案编号可按约束生成保留变体，每个变体由独立的可行性求解或参考策略先验收。

### 新版评分与校准

| 独立业务成果 | 建议权重 | 证据 |
| --- | ---: | --- |
| 可用资金和义务重建 | 20 | 按实体、币种和交收时点正确计算，引用有效版本，识别受限和占用 |
| 主动发现与可执行计划 | 20 | 在业务期限前识别风险，提交满足当时约束的授权及资金安排 |
| 动态修订与实际执行 | 35 | 处理 M1 改版、FX 失败和结算回执，按有效金额支付三笔义务，避免重复占用 |
| 残余风险和成本 | 20 | GBP 缓冲、USD 付款保障、资金与抵押品占用、交易成本和回收安排 |
| 可核验交接 | 5 | 余额、未偿融资、限制与后续期限能从可信流水复算 |

同一付款事实只支持一个成果检查，其他分项须有独立证据。业务原始分与授权或重大失约状态分别保存，报告逐项分数及失效位置。具体判据、权重和通过规则在新版本实测前冻结，既有 94.17 分运行保留原成绩。

先校验参考策略和边界变体，再使用本次 MiniMax 基线及其他同档模型或成熟 Agent 做小规模校准，固定 prompt、工具权限和预算，每个条件重复执行。实测明显高于 40 分时，依据轨迹增加尚未测到的业务依赖；出现大面积失约时检查可行性、规则口径和时间窗口。最终用独立保留变体检查目标分布，按业务场景聚合。达到 30–40 分目标的结论留待该新版本真实运行后给出。

## 新挑战题源的落地与校准

当前0.8.0将GBP付款保障、USD到期义务、融资共享总限额、抵押品与出售共用持仓、MMF两窗口共享额度，以及早于本金到期的10:35银行指令批次放在同一班次。Agent需要从原始lot记录自主识别所有权、币种、交收、到期、外部抵押和内部占用。Repo报价给出类别haircut及银行额度，不再给出最优抵押组合。

当前评分为联合资金组合40、真实付款25、实际净缓冲15、到期本金偿还20。联合组合取内部融资限额、预计首笔付款及维护抵押后的GBP缓冲、USD义务保障三项连续分的最低值。不采取资金动作不能凭“未超限”获得免费分。C1仅在repo实际触发现金抵押品义务时参与付款分母。

0.8.0的同版三次结果：MiniMax-M3.1-Flash为100、100、100；MiniMax-M3为80.09、52.04、52.04，均分61.39、样本标准差16.19。当前不能声明达到30–40分。没有把校准失败的版本投入保留验收，也没有改写旧分数。下一阶段[从原始证据推导风险](financial-source-risk-case-design.md)已实现为独立题源，三种情景及各自保留金额变体均有100分参考路径，模型重复实测另行报告。

一条完整作者路径为：按G1、G2当前市场价值分别分配repo抵押品取得GBP20.4，standby取4.6，合计融资25；出售独立T1取得3.92，早窗赎回MMF4，独立窗口USD7换GBP5.32。可用GBP为14+20.4+4.6+3.92+4+5.32=52.24，缴付C1的3和M1的44后余5.24。剩余MMF6及10:20来款2覆盖M2的8。10:35前排队的本金偿还在11:00/11:10检查现金，10:40和11:05来款支持交收。该路径及保留金额变体由作者策略验证，步骤不进入被测工作区。

逐轮真实执行显示，独立融资渠道、通知改版和单次故障不足以形成稳定挑战；第五级曾得到100分。第六级发现消极不融资仍可获40分的rubric问题，已在新版本消除。第七级两模型的单次成绩26.25与60分，第七级修订首轮30.72与16.67分，证明单次高低分和跨版本均值都不能支持难度声明。第八级冻结后按相同模型、Harness、题包、参数做重复，并将保留金额变体与校准样本分开。

真实运行和环境失败均保留。当前仅覆盖同一场景家族、MiniMax两型号及JSON动作Harness；不能据此断言所有成熟Agent已经达到30–40分目标。[执行账本与统计](../examples/treasury-network/README.md)

`benchmarks/treasury_network/build.py` 将当前级别冻结为 `dataset.toml + tasks/treasury-duty/`。每次生成独立目录，包含工作区、私有事件配置、独立控制器、ground truth 和命令 Judge。生成器拒绝覆盖；文件摘要、平台 release digest、Agent/Workflow 修订、模型、参数和原始轨迹随运行保存。

五级递进覆盖多实体和多币种资金、受限现金、报价与审批、通知改版、FX 匹配失败、银行未分配来款、SSI 改版以及融资到期偿还。第五级增加回购现金抵押品维护义务 C1，以及 09:17–09:25 的独立 Dealer B 换汇窗口。资金并非只要提前多借就可忽略后续变化；Agent 还要处理维护现金占用、已排付款版本和融资本金到期。

第五级的一条作者侧可行路径：初始 GBP 可用 14、repo 20.4、line 12、短票净收入 3.92；支付 C1 的 3 后，支付修订 M1 的 44 并维持 5 缓冲仍需 GBP1.68。独立窗口卖出 USD3 得 GBP2.28，可留下 GBP5.6，同时仍保留足够 USD 支付 U1。赎回 8 支付 M2；10:40 与 11:05 的来款支持本金偿还。全部 repo 偿还后释放先前缴付的现金抵押品。此段只存在于作者侧设计稿，未放入被测 instruction 或工作区。

初始 instruction 只有岗位、目标、权限、交付物和资料入口。工具说明给出字段、单位、异步语义、幂等和处理时间，不指定调查或融资顺序。未来材料发布前不可读取或搜索。市场消息和独立 Fund Q 档案提供真实类型的旁置信息。金额与时点同时显示机器值和可读值，防止把纯换算困难当作主要挑战。

前三级冻结权重为付款30、缓冲15、偿债25、费用25、交接存在性5。第四级起删除简单交接存在性分，偿债提高到30，并将未付的此前 GBP 到期负债纳入净缓冲。费用项包含支付与缓冲达成前提，其相关性单独披露。没有全题归零门槛；环境失败记为未评分。

真实试跑使用用户已有的 MiniMax 加密连接。第一轮发现 repo 报价字段歧义，保留原结果并修正后续题包；第二轮修正报价后模型得分91.36，三笔付款、缓冲和偿债全部完成，证实通知改版与简单长链路仍不足以形成正式挑战。后续试跑记录网络、限流和日志协议故障，按环境问题处理，并保留重跑版本。达到30–40分的结论仍须依据同版重复与保留情景，而不能把版本间的五次分数混为同版均值。
