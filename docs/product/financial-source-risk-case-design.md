# 下一轮：从原始证据推导流动性风险

状态：已实现为 `benchmarks/source_treasury`，当前生成0.3.0并进行冻结协议的重复实测，尚未达到正式挑战验收条件。不得将本文的解题分析复制进被测instruction。

## 为什么需要换一个能力重心

Treasury network的前八轮已实际运行。补全接口语义、保留模型reasoning和修复长程会话传输后，MiniMax-M3.1-Flash在0.8.0的三次执行均得100分，M3三次均分61.39。模型能查阅合同、组合资金、处理银行suspense、更新支付版本、分配抵押物，并对未来来款提前排偿债指令。单纯增加步骤、文件或截止时间不足以构成稳定挑战。

当前题目仍给出了可信可用余额、结构化的义务记录和直接的风险预测。下一轮应检验Agent能否自行建立这些中间事实，随后再把分析转成真实指令。不能通过不完整接口、单位歧义或隐藏必要信息降低分数。

## 一条连续工作流

Agent接管一个组合的日内资金、风险台账和保证金运营。开场为普通值班，随后市场资料和内部数据分时送达。正式追缴出现之前，公开的交易、合成协议和市场数据已足以推导风险；付款通知只确认义务，不提供前置调查步骤。

初始instruction只给岗位、业务目标、权限、交付物和资料入口。工作区采用真实类型的资料：银行分录、客户资金归属、现金限制、衍生品交易、CSA附件及修订、已交VM/IM、市场变动、结算通知和一般新闻。材料带明确业务生效时间、送达时间、记录ID、修订关系和来源。

## 要测试的独立能力

1. **现金和实体重建。** 从逐笔分录、在途项目、受限资金及账户法律归属计算某截止时间可用的现金。保留重复投递、冲正及同一事件跨系统映射，所有处理规则均可查证。
2. **协议与敞口推导。** 按合成协议的适用范围、交易日期、币种、净额集合、threshold和已交VM推导追缴。IM是否抵扣VM由题内合成协议明确规定。旧风险缓存可有错误或落后，但不能直接把正确答案放在新预测字段中。
3. **主动发现与执行。** 市场资料和持仓足以推导风险后，观察风险台账是否及时修订，能否在融资窗口关闭前形成可执行安排。保持当前已经验证的资产占用、共享额度和银行指令语义。
4. **状态纠偏。** 后续修订改变某些交易的净额范围、合格抵押物或到账状态；Agent应追查受影响的具体义务和资源。不同场景同一消息可能对P形成不同敞口，避免固定见新闻就全额融资。

合成协议中的一个作者示例：同一有效净额集合MTM为−18和+6，threshold为2，已交VM为3，则补充VM为7；若另有IM为4且协议不允许抵扣VM，错误缓存可能给出3。它检验协议适用与数据关联，不依赖真实法律规则或不可获取的知识。最终数值需结合全工作流求解并验证可行性，不能直接沿用本示例作为任务答案。

## 工具与数据边界

- `read/search`读取当前已发布资料；不会通过文件名提示事件类别或推荐处理路径。
- 提供只读SQL或等价表格计算能力，支持公开数据的筛选、聚合和关联，避免把手工算术作为主要门槛。工具只装载当前公开表，禁止外部文件、ATTACH、扩展和写入；记录查询、结果和耗时。
- 风险台账写入接口仅确认记录，不反馈预测是否正确或返回标准答案。
- 资金及资产操作的参数、权限、排队、截止、费用、占用和释放语义必须完整。工具不能代替Agent挑选净额集合、计算正确风险或生成最优组合。

## 评分与验收约束

当前冻结权重为前置风险重建40、联合资金可行性30、付款15、实际缓冲5、资金控制10。数值连续计分，来源引用单独报告，不因一个格式字段缺失整题归零。联合资金与实际缓冲存在相关性，因此后者只占5分，二者分别核查资金组合及实际交收后状态；仍需通过真实错误类型审查区分度。

至少保留压力、较弱冲击和实际已对冲的对照变体。评价成本时使用当时已公开的信息与可执行策略，不按未来已知结果要求Agent事后择优。历史轨迹、旧分数和旧rubric原样保留。

先实现独立的Python事实重建参考与可信账本，校验完整成功路径、空跑、只等正式通知、全额抢融资、误用IM、跨实体挪用等基线。再用固定模型和成熟Harness开展重复校准，最终使用未参与改题的变体验收。原有0.8.0只作为运营能力基线，不自动升级为正式挑战。

## 已实现的范围与尚待验证项

- 原始银行账面、有效限制、交易生命周期/修订/重复投递、跨法人持仓、产品净额范围、VM/IM区分及市场因子已实现。正式通知前，公开资料足以独立推导追加VM；新风险预测不直接给出答案。
- 模型侧可使用只读SQL和有界计算器；SQL只装载当前已公开CSV。数据工具不接触Judge、私有未来事件或平台数据库。
- 风险报告只返回记录编号，不返回正确性。完整正确路径由独立Python重建器及可执行资金策略验证，三情景×两金额变体均可100分。
- 0.1.0/0.1.1/0.2.0的原始试跑及缺陷分别保留；0.3.0在第一次调用前冻结评分与工具，不将新公式套用到旧轨迹后宣称真实新成绩。
- 0.3.0使用整本台账一个GBP5m绝对误差预算：多个CSA的错误共同消耗同一现金缓冲；原逐CSA独立预算会容忍超过整体流动性承受能力的总误差。现金部分、权重和正式通知前后的时间系数保持不变。
- 当前保留变体只改变金额，不能代替独立机制或新场景家族。合成资料尚未包含前述全部协议修订及冲正机制；更丰富的动态修订属于后续新版本。
